# F-001: Engineering and design-system foundations: Security Review (G4 design)

> Phase 4 security pass · Reviewer: security-reviewer (agent, read-only) · Date: 2026-09-25 · Branch `design/F-001`
> **Scope:** the F-001 solution design (`design.md`, working-tree draft of 2026-09-25) and brief. It covers the core tasks T01–T15 and the optional BC-11 tasks T20–T25, checked against `docs/architecture/security.md` §5.8 RF-1…RF-7, §8.1 P0-9, §8.4 PG-1, SR-03, SR-28 and ADR-0012/0027. Current repo state reviewed: `.github/workflows/ci.yml`, `.github/workflows/release.yml`, `package.json`, `pnpm-workspace.yaml`, `.claude/settings.json`. Read-only GitHub API checks (2026-09-25): `actions/permissions/workflow` → `default_workflow_permissions: read`; `actions/permissions` → `allowed_actions: all`, `sha_pinning_required: false`; collaborators → 2 accounts, both `admin`. Nothing was exploited or run against real systems.
> Labels: **Confirmed** = verified in files, registry metadata or vendor docs. **Suspected** = inferred; verify at implementation.

## 1. Assets, trust boundaries, entry points

| Item | Description |
|---|---|
| Assets | `main` branch integrity; `v*` tags and GitHub Releases (later: images, charts, the air-gapped bundle under ADR-0027); `GITHUB_TOKEN` and future release/signing credentials; developer and agent workstations; the lint and scan gates themselves (config files); private source code |
| Trust boundaries | Developer or agent workstation → GitHub (push); PR branch → CI runner (untrusted code runs with the job token); npm registry, GitHub Actions marketplace, MCR and GitHub release binaries → CI (supply chain); CI → deps.dev and OSV API (metadata egress); tag push → release workflow (`contents: write`) |
| Entry points | `git push` of any branch or tag by any write-access identity (2 admins, org 2FA not enforced); PR-modified workflow and config files; `pnpm install` on workstations and CI; third-party actions and binaries; Claude Code agents acting through the permission allow-list in `.claude/settings.json` |

| SEC-F001-01 | **The CI gates don't gate anything on GitHub Free.** The repo is private on Free, so there are no rulesets, branch protection or required checks, and org 2FA isn't required. Two accounts have `admin`, and development agents push with a human's git credentials. Any write-access identity, a stolen token or an agent can push to `main`, merge a red PR, or push a `v*` tag that runs `release.yml` with `contents: write`. Every "blocking" gate in this design (gitleaks, OSV, licence, lint, axe) only produces a red check. Likelihood M, impact H today (the release holds source and notes only). | SEC-F001-02 | **The `verify` job in T25 checks itself.** A tag push runs the `release.yml` that sits **at the tagged commit**. P0-9 is not met, and F-002 to F-005 build on an unhardened pipeline. The product owner must accept this in writing with an expiry no later than the first customer-operated artefact (PG-1).

## 5. Recommendation on BC-11

**Accept BC-11, with changes.**
1. Move **T20** (pins, permissions, `persist-credentials`) and **T22** (lifecycle-script test) into core. Both are small, have no behaviour change, and are P0-9 must-haves.
2. Accept **T23** (SCA and licence) with the SEC-F001-15 gate changes.
3. Accept **T21** (Renovate), self-hosted, only after the Team upgrade (SEC-F001-17).
4. Accept **T25** only **together with the GitHub Team upgrade**. On Free it adds workflow code and no security (SEC-F001-02).
5. Keep **T24** (CodeQL) conditional on licensing, and record the SAST gap.

BC-11 without a plan upgrade does not close RF-5 and should not be presented as doing so.

## 6. Required changes before G4

1. §6.5 and §11.8: state that the tag ruleset is the RF-5 control and `verify` is a consistency check (SEC-F001-02). Record Option A as a deviation from SR-28 with an expiry (SEC-F001-03). Make the Team upgrade and org 2FA prerequisites for T03 onward, or attach a signed risk acceptance (SEC-F001-01).
2. Move T20 and T22 into core. Add "enable the repo SHA-pinning policy, restrict allowed actions, `persist-credentials: false`" to T01 or T03 (SEC-F001-13).
3. §6.2: separate artefact config or anchored allow-list; `fetch-depth: 0` with a non-empty-range assertion; git-mode and artefact self-tests with an explicit `--config`; custom provider-key rules; pre-commit and agent hooks (SEC-F001-05, -06, -07, -24).
4. §6.1: remove the `@ai-sdk/react` exemption. Ban `ai`, `@ai-sdk/gateway`, `@anthropic-ai/claude-code` and in-process inference libraries. Resolve aliases, check dev closures, ban non-literal `import()`/`createRequire`, turn on `no-unlimited-disable`, and state that egress policy is authoritative (SEC-F001-08, -09).
